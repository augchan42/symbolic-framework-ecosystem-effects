## High Severity

### 1. Hardcoded dataset manifests are duplicated and inconsistent

- File path and line: `scripts/extract_han_orders.py:28`, `scripts/extract_reasoning_lengths.py:16`
- Severity: high
- Category: Holistic
- Description: Dataset membership is hardcoded in multiple scripts and is already inconsistent. `extract_han_orders.py` defines a clean N=41 dataset with newer May 2026 game IDs, while `extract_reasoning_lengths.py` uses a separate `DATASET` list containing different control/yarrow games. This makes reproduced tables depend on which script an agent edits or runs, and creates a high risk of silently mixing incompatible experimental cohorts.
- Suggested fix: Move dataset manifests into one versioned data/config file, for example `data/dataset_manifest.csv` or `config/datasets.yaml`, and have all extraction/analysis scripts read from it. Include cohort name, condition, game ID, relative path, and inclusion rationale.

## Medium Severity

### 2. Appendix claims complete prompts but omits important prompt context

- File path and line: `paper/main.tex:438`
- Severity: medium
- Category: Diff
- Description: The appendix says it reproduces the "complete user-facing prompt," but the added text later says diplomatic messages and previous-game memory injections are omitted. This creates a reproducibility problem: readers are told the prompts are complete when important prompt context is intentionally excluded.
- Suggested fix: Change the wording to "representative prompt excerpts" or include the full prompt text, including diplomatic messages and memory injections, in the appendix or supplemental artifact.

### 3. External engine path configuration is scattered and inconsistent

- File path and line: `scripts/extract_reasoning_lengths.py:13`, `scripts/extract_han_orders.py:23`
- Severity: medium
- Category: Holistic
- Description: External integration configuration is scattered and inconsistent. `extract_han_orders.py` supports `WARRINGSTATES_ENGINE`, but `extract_reasoning_lengths.py` hardcodes `Path.home() / "projects" / "warringstates-engine"`. Agents and new contributors can run one extractor successfully while another silently targets a different local layout.
- Suggested fix: Centralize external paths in a shared config/helper module, document `WARRINGSTATES_ENGINE` in README/agent docs, and make all scripts fail fast with the same actionable error when the engine repo is missing.

### 4. Agent harness is incomplete and Claude compatibility is not symlinked

- File path and line: repository root, `CLAUDE.md:1`
- Severity: medium
- Category: Holistic
- Description: The requested agent-readiness standard is not met. There is no `AGENTS.md` at the root or in major directories such as `scripts/`, `data/`, `paper/`, and `docs/`, and root `CLAUDE.md` is a standalone file rather than a compatibility symlink to `AGENTS.md`. Directory-specific conventions, safe edit boundaries, generated-file rules, testing expectations, and common pitfalls are therefore not discoverable to non-Claude agents.
- Suggested fix: Add root `AGENTS.md` and symlink `CLAUDE.md` to it. Add focused `AGENTS.md` files for `scripts/`, `paper/`, and `data/`, with matching `CLAUDE.md` symlinks where compatibility is needed.

### 5. No automated test, lint, type-check, or CI harness exists

- File path and line: repository root
- Severity: medium
- Category: Holistic
- Description: The repo has reproducibility scripts, but no tests for core classification logic, data schema assumptions, statistical helper behavior, or expected output invariants. This leaves agents without a fast way to validate edits beyond manually running the full reproduction command.
- Suggested fix: Add a minimal `pytest` suite for pure functions and CSV schema invariants, plus a lightweight CI workflow or Make target such as `make test` or `make reproduce-check`. Consider `ruff` for linting and basic formatting consistency.

### 6. Analysis script performs file I/O and computation at import time

- File path and line: `scripts/table_content_independence.py:15`
- Severity: medium
- Category: Holistic
- Description: One analysis script performs file I/O and computation at import time, unlike most other scripts that use `main()`. This makes the script hard to test or reuse and can surprise agents importing helper functions such as `dominant_posture`.
- Suggested fix: Move all executable work into `main()`, keep constants and pure helper functions import-safe, and add `if __name__ == "__main__": main()`.
